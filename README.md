# RITMO

Адаптивный MVP магазина повседневной одежды, русский интерфейс, цены в UZS. Next.js 16 / React 19 / TypeScript / Tailwind 4, Prisma 6 с JavaScript engine и SQLite-адаптером, Argon2id, Google GenAI SDK.

## Быстрый старт

Нужен Node.js 22 LTS. В этой облачной среде Node 22 также устанавливается как dev dependency: npm scripts автоматически используют его. Нативный better-sqlite3 собирается под версию Node, используемую при установке.

```sh
cd /workspace/project
cp .env.example .env  # только если .env ещё нет
export npm_config_cache=/workspace/.npm-cache
npm ci --ignore-scripts
# Сначала активируем Node 22, затем собираем нативный драйвер под него:
npm rebuild node
export PATH="$PWD/node_modules/.bin:$PATH"
npm rebuild better-sqlite3
npm run db:push
npm run db:seed
npm run dev
```

Production: `npm run build`, затем `npm start`. Порт по умолчанию 3000. `db:seed` повторяем: обновляет только демонстрационные изображения, сохраняет остальные данные товаров и остатки. SQLite хранится в `prisma/dev.db`; относительный DATABASE_URL разрешается относительно каталога prisma, абсолютный `file:/...` тоже поддерживается. Файл БД не коммитится: настройте постоянный диск и резервные копии. Для нескольких экземпляров/бессерверного хостинга требуется переход на PostgreSQL, его Prisma datasource и адаптер; текущий вариант рассчитан на один Node-сервер, не на эфемерный диск Vercel.

## Конфигурация

- `DATABASE_URL=file:./dev.db` — локальная база без внешней службы.
- `GOOGLE_API_KEY` — только на сервере. `GEMINI_MODEL=gemini-2.5-flash`. Без ключа чат сообщает о недоступности, покупки работают. Запрос ограничен 1000 символами и 15 секундами; в модель не передаются профиль, заказы или история чата. Рекомендации проходят проверку ID по каталогу; карточки содержат серверные цены.
- `APP_URL` — точный origin приложения, например `https://shop.example.uz`. Используется для CSRF и ссылок восстановления; установите при публикации за reverse proxy.
- `SMTP_URL`, `MAIL_FROM` — почтовый транспорт и отправитель для восстановления пароля по email. Без них форма честно сообщает о недоступности. Для аккаунтов только с телефоном SMS-восстановление пока не реализовано.
- `SESSION_SECRET` из исходного SPEC не требуется: сессии используют 256-битные случайные непрозрачные токены, в БД хранится только SHA-256 токена, а не подписанный cookie.

Не включайте секреты в NEXT_PUBLIC_ переменные, git или сообщения чата. Production должен работать по HTTPS: cookie HttpOnly / Secure / SameSite=Lax, срок 30 дней. Пароли — Argon2id. Изменения проверяют Origin. Лимиты хранятся в БД, включая ограничения по идентификатору аккаунта и общие для экземпляра; IP-заголовки не считаются доверенными. Для публичной высокой нагрузки настройте отдельный rate limiting на доверенном reverse proxy. Токены восстановления одноразовые, действуют 30 минут, смена пароля завершает все сессии.

## Что работает

Главная, каталог с поиском/категорией/цветом/размером/ценой/сортировкой, страница товара, избранное, корзина в localStorage, гостевой и авторизованный checkout, регистрация по email/телефону, вход/выход, профиль с адресом и собственной историей заказов. Сервер пересчитывает цены, объединяет дубли вариантов и атомарно списывает остатки с откатом при ошибке. Доставка 25 000 UZS, бесплатно от 500 000 UZS; только наличные. Валюта — целочисленная UZS. Интерфейс на русском; строки и форматирование можно вынести в словари при добавлении узбекского.

10 товаров и их характеристики — демонстрационные. Фотореалистичные изображения сгенерированы ИИ и хранятся локально; они иллюстративные. Перед реальными продажами замените их подтверждёнными фотографиями изделий. Доставка/оплата, юридические сведения, контакты и возвраты явно помечены как демонстрационные, реальные интеграции не подключены. Таблица размеров ориентировочная. Для реального запуска замените эти данные и опубликуйте юридические условия.

## Проверки

```sh
npm test              # расчёт доставки, серверные цены, атомарность и остатки
npm run typecheck
npm run build
npm start             # отдельный терминал, нужен для browser-тестов
npm run test:e2e       # Chromium, по умолчанию /usr/bin/chromium
npm run test:cleanup   # удалить только зарезервированные E2E-данные, вернуть остатки
```

`CHROMIUM_PATH` задаёт иной путь к браузеру. E2E создают тестовых пользователей и заказы и изменяют демонстрационные остатки; запускайте против тестовой БД, не production. Unit-тест очищает созданные им товары/заказ. Нет внешних вызовов Gemini и SMTP в тестах без явно настроенных сервисов. Все изображения локальные; внешняя сеть при просмотре магазина не нужна.
